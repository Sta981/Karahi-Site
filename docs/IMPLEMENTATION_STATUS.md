# Foundation V2 — implementation and verification report

## Delivered
- Preserved the latest premium customer site, logo assets, animation code and menu flow; added customer account hub and a separate branded management login.
- Seven seeded access roles, linked employee onboarding, active account checks, role permission table and server-side guards. Owner-only legacy admin routes. Manager can create/disable non-manager employees, owner can additionally manage managers. Fixed permission policy currently seeded at startup, not a configurable permission designer.
- 63 SQLAlchemy models, 84 FK declarations, one connected component; exact model-derived ERD and dictionary included. Twelve additions match the agreed target.
- Manager overview, kitchen ticket workflow, waiter table order and assigned-order view, cashier partial payments, stock batch receipt, purchase approval/receipt, cash register, shift scheduling, attendance, expenses, team messages, customer service requests. Owner analytics no longer uses invented fallback figures. Public checkout records pending payments; guest order access uses signed token. Reservation conflict check covers two-hour overlaps.
- Protected transactional tables cannot be edited/deleted via generic admin CRUD. Reference data retains existing generic CRUD; correction/cancellation operations should be domain-specific. Not every table has dedicated full CRUD; this is still a rubric coverage gap, not a claim of complete marks.

## Verified in this environment
- Python source compilation; Jinja syntax parsing of 37 templates; JS syntax checks.
- `tools/check_schema.py`: installed SQLAlchemy mapper configuration; actual SQLite DDL with FK enforcement; schema count and graph connectivity; recipe deduction once; invalid repeat preparation rejected; unpaid completion rejected; partial payment and overpayment rejection; paid completion succeeds. Test uses a lightweight SQLAlchemy binding instead of Flask-SQLAlchemy, so these are model/service checks only.
- Flask integration pytest collection attempted; blocked by ModuleNotFoundError: flask. Dependency installation attempt failed (no available package index). New tests added but not executed. No browser or accessibility end-to-end test was performed for V2.

## Limitations and release gates
- This is a fresh database development build. No Alembic migrations or old database conversion implemented. Existing V1 database must be backed up; use new file. Startup checks missing columns, not every old constraint.
- Retains existing USD menu and older customer-facing assets; PKR/local address conversion and new branding acceptance remain pending. Legacy monetary columns remain Float, with Decimal validation for new financial actions; production-wide Numeric migration, accounting reconciliation, refund workflow and payment gateway still needed.
- Waiter currently starts a single-dish dine-in order; multi-dish cart/editing, per-item kitchen tracking, food-served state, table assignment and real-time updates remain incomplete. No push notifications or WebSocket support. No delivery rider workspace; no automatic delivery route planning.
- Inventory consumes configured positive recipe quantities at preparation. Unconfigured recipe items do not deduct stock. Demo recipe quantities are fictional; review before production. No stock adjustment/waste workflow or margin analytics yet. Purchase order UI supports one line per draft. Cash register records counted balances but is not reconciled to payments. Expenses register is not a full P&L. Attendance/shift scheduling are basic, not full HR/payroll processing.
- Existing public review, cart, profile and admin reference-data screens retained; comprehensive record-level audit and data integrity tests, login rate limiting, password reset, MFA, deployment hardening and stress/concurrency tests remain release gates. Reservation times use local naive dates; timezone handling and simultaneous booking load tests required. Existing loyalty earning was disabled at unverified checkout; award on settled payment and reverse on refund remains pending.
- User-facing figures are derived from database records, but synthetic demo records are intentionally seeded if RESTRO_DEMO=1. Do not deploy this demo mode publicly. Management portal role navigation and permissions must be checked in runtime. No guarantee of marks or production readiness.
